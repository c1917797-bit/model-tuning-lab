Mechanism

核心点：用“保秩的结构化选列”缩小递归状态

它到底在优化什么？

线性注意力或 Gated DeltaNet 用递归状态承载历史信息。状态矩阵的一条轴由 key dimension d_k 决定。若 Q/K 激活的有效秩明显低于 d_k，就有机会删掉冗余通道。

DRRQR/Strong RRQR 的角色不是直接“加速”，而是在校准激活上选出尽量保持列空间的一组通道；真正让部署栈变小的是后续对 Q/K 权重、配置与状态形状做一致的结构化切片。

St ∈ ℝdᵥ×dₖ　→　Q′ = QP, K′ = KP　→　S′t ∈ ℝdᵥ×r, r < dₖ
一句话：先用 rank-revealing QR 决定“哪些 Q/K 通道最值得留下”，再同步裁剪，让 recurrent state 真正从 128 缩到 r。
1 · 低秩假设训练后的 Q/K 表征存在冗余，校准激活的有效秩小于原维度。
2 · 保秩选列Strong RRQR 选择更能保持激活子空间的通道，而非机械取前 r 维。
3 · 结构化裁剪同一索引同步作用于 Q 与 K，保持 dense、轴对齐的运行形态。
4 · 端到端验证只有精度门、重复性能与热路径证据同时通过，才能谈采用。
Architecture fit

为什么能穿刺 Qwen3.6-27B，又为什么上限可能不大

模型内的作用范围

64 层中，48 层是 GDN/线性注意力，16 层是 full attention；每 4 层为 3×GDN + 1×Full Attention。本次只改变 48 个 GDN 层的 Q/K 相关张量，共 96 tensors。

GGGFGGGFGGGFGGGF

示意为 16 个四层组中的代表片段；G=GDN，F=Full Attention。

收益成立的四个必要条件

  1. 秩：校准激活确实有可剪冗余。
  2. 质量：被删除通道对目标任务不关键。
  3. 执行：昇腾算子真实消费变小的 head_k_dim，不是只改配置。
  4. 系统：节省大于全注意力、MLP、通信、调度与框架开销。
关键认识：Dk 减半不等于整模型时间减半。它只缩小部分层、部分张量和部分算子；端到端增益天然会被 Amdahl 定律压缩。

Reusable knowledge

哪些经验可以迁移到下一篇论文

继续复用的成功做法

  • 冻结论文/代码 commit、关键文件 SHA、模型、镜像、数据、prompt、scorer、traffic shape 与资源 lane。
  • 把“结构审计、真实权重 smoke、质量、性能、profile、最终审计”拆成依赖门。
  • 持久化逐样本结果，只续跑未接受的 index；服务中断不抛弃已经验真的行。
  • 比较重复分布而不只看均值；以 baseline 实测波动定义质量门。
  • 保存 rejected、failed、inconclusive 结果，不把失败代码留在最终安全树。
  • 结论分层：机制、实现、算子、服务、全模型、adoption 各自有独立证据。

这次暴露的高风险陷阱

  • 校准偏差：LongBench 家族校准后，LongBench 增益不能证明泛化。
  • 强度误判：更小剪枝比率不必然更高精度；Dk96 的 GSM8K 反而比 Dk64 更差。
  • 均值幻觉：2.7% 的均值变化若区间重叠，不能写成稳定收益。
  • 设备映射：host 4-7 在容器内是 0-3；写错会在启动前失败或伤及其他任务。
  • 路径失败：launcher 多写一个不存在的 scripts/ 组件时应归类为 orchestration failure，不能算算法失败。
  • 无损夸大：通过有限门限最多是“未观察到实质退化”，不是数学或通用意义的 lossless。
