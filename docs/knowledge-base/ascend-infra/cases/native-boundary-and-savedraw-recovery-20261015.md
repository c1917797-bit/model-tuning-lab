## Decisions changed by this evidence

- **Loaded source is not executed integration.** The native descriptor-copy path originally missed the official Ascend worker memcpy patch and reached a generic compiler abort. The correction loads the installed official patch in the actual child before using the native copy path; source hashes or a CPU import alone do not prove that runtime binding. Subsequent024repair3 and031 producers completed the registered native copy captures with bitwise results. This closes that particular loading defect, not a whole-model or all-shape qualification. The original repair2 abort Ref still needs a final hash audit before being cited as an exact artifact below.
- **Separate arithmetic domains before blaming the algorithm.** In the actual024repair3 B1 step0 raw, whole-core peer output0/state3.85577e-8 and changed-decode output0.00235916169/state3.88127e-9 pass their original limits, while unchanged chunk64 prefill versus ideal CPU64 gives output0.00381409/state0.002278857 and fails. BF16-input/output chunk prefill and FP32 recurrent/deferred state do not inherit the same ideal-reference precision contract simply because one consumer visits both. Keep all ideal metrics and the old FAIL. Any explicit unchanged-native boundary contract must still prove the actual call, operands, returned state/output and writeback; keep hard independent gates for the changed decode/flush/copy. This observation is not a general exemption for native kernels.
- **Worst request means worst request.** A B16 global metric can hide a small request: truth[[1000],[1]], second output error0.01 gives global1e-5 but per-request0.01; state error1e-5 similarly hides below7.92e-7 globally.031 adds independent per-request decode and selected-slot/native-peer metrics with the original thresholds, retaining global metrics as diagnostics. Its local oracle starts from captured before-state; seed/continuity checks do not turn it into a wholly independent accumulated trajectory oracle.
- **A BF16 point-reference failure still needs precision-domain attribution.**031 compares actual BF16 decode output directly to uncast FP64 output. A software counterexample has correct nearest BF16=1 for truth1+2^-8-2^-30 yet uncast normalized error exceeds0.00303. This proves a possible contract floor, not the cause of any real row and not a new numerical PASS. Saved-raw diagnosis should separately retain uncast error, direct-RNE floor, native peer and actual pre-cast evidence if available;031 has no actual FP32 sidecar and cannot borrow016's sidecar qualification. Separately, the actual builder represents one-token decode lengths as `[0]+[1]*B`; the old checker expected `arange(B+1)`, a checker ABI defect hidden by B1. Read actual source contracts before classifying either failure.
- **Verification-only raw hashing must remain streaming.**027 first verified the raw hash in chunks, then called `read_bytes()` anyway for opaque151MB frames. Host VmHWM exceeded the original256MiB owner/child bound before the independent consumer ran.027repair1 keeps source/JSON reads unchanged and streams the three verification-only loops: target closure, initial checks and final checks. Do not return fake empty bytes, raise the RSS budget, omit raw Refs or call a resource failure numerical. Same-image CPU recovery then ran the original consumer and preserved its actual first numerical FAIL.
- **A non-atomic proc frame is not a final attribution.** Docker-top can list a short-lived compiler descendant while `/proc/stat`, cgroup and cmdline are read at different instants.024repair3 and031 both completed40 NPU raw records but their owners failed observation. Continuing presence, reuse, permissions, unknown parent and protected PID cases still fail. This is an unverified repair until its real runtime evidence exists; a fixture does not prove departure.
- **Recover completed raw before spending another NPU run.** Preserve the failed owner and use the existing bounded Devices[] owner to run the unchanged original consumer first, then any explicitly new diagnostic consumer. Mount every real dependency, including CPU Meta, both initial anchors and exact host snapshots of container source paths. Do not treat `/vllm-workspace/...` as a host path. New consumers and diagnostic ownership completion cannot retroactively make the old owner PASS. Prefer a thin change to the existing owner over another general safety framework.
