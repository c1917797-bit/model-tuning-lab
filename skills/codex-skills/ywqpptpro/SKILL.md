# Tech Insight Deck Pro

把技术变化、代表性进展、论文洞察与学术资源组织为一条可审阅的技术主线。必须先生成 Markdown/HTML 预览，获得用户明确确认后才生成 PPT。

## 固定叙事顺序

1. 封面
2. 技术趋势洞察：每个技术阶段紧邻一个代表性进展、真实图片与一句洞察观点
3. 洞察摘要：按决策问题归纳方向
4. 技术清单：方向、技术、价值简述
5. 单项技术洞察：每篇论文一页，用真实架构图和实验图支撑判断
6. 学术资源洞察：高校、实验室、教师与代表课题
7. 技术洞察观点：三个按主题命名的观点板块、待解问题与建议
8. 致谢

## 开始前必须读取

- 研究、筛选和写作规则：[references/methodology.md](references/methodology.md)
- 完整数据结构与字段限制：[references/content-schema.md](references/content-schema.md)

## 工作流

### 1. 定义决策问题

明确业务决策、技术边界、时间窗口和目标受众。信息不足且会改变研究路线时，最多询问两个关键问题；其他细节使用保守假设并在预览中标注。

### 2. 研究并建立趋势主线

检索最新的一手来源。优先最近 18 个月的论文、会议、标准、官方技术博客和产品资料；基础工作可超出时间窗口。所有可能随时间变化的事实必须联网核验。

先写 `trend_insight.stages`，每个阶段分配唯一 `stage_id`，例如 `T1`、`T2`、`T3`。每个阶段同时写清技术变化，并选择一个能把变化说具体的系统、项目、标准或论文。代表性进展必须包含机构/团队、日期、技术事实、来源链接、真实图片和图注；产品宣传语、无来源截图或无法核验的转述不能采用。

保持以下内容关系：

`技术阶段 T# → 洞察方向 D# → 论文/技术页 P# → 高校与教师课题 → 技术洞察观点`

每个 direction 和 technology 的 `trend_link.stage_id` 必须引用存在的技术阶段。趋势页每一行左侧写变化、右侧紧邻代表性进展，不再拆成彼此独立的“演进”和“材料”两栏。页面只在底部保留一句 `viewpoint`。

研究方法留在工作过程和数据字段里，不把分类术语写成页面标题或标签。页面不出现“证据依据”“业界实践”“最新论文”“核心判断”“决策含义”等字样。

### 3. 准备真实图与完整 spec

趋势页每个阶段的代表性进展必须配一张真实图片；每个技术页必须包含真实的系统/架构图与实验结果图。技术背景在内部用 `current_state`、`pain_point`、`research_question` 三个字段保证内容完整，但预览和 PPT 必须把三者合成一个自然段，不能显示“现状：”“痛点：”“问题：”等字段标签。自然段先交代当前对象、场景和约束，再说明由此出现的瓶颈或风险，最后引出本页课题需要解决的问题；不能写成技术定义或泛泛介绍。

按 [references/content-schema.md](references/content-schema.md) 的版面预算约束技术背景、技术细节、实验方法与结果和洞察启示。不得把超量文案交给 PowerPoint 自动缩小字号。

- `tech_detail_summary`（核心思想）：一句适合人读的完整表述，说清楚解决了什么问题、整体思路是什么，可以比分点略长；不含冒号标签，加粗的“核心思想：”前缀由 `build_deck.py` 自动添加。
- `tech_detail_points`（关键技术）：2–3 项，写成“关键技术名称：简述”，技术名称必须是真实的机制/模块名（如“动态稀疏注意力”），会自动加粗，不能用“机制”“设计”“边界”这类空泛标签代替；渲染时统一放在“关键技术：”小标题下，每项自动加“• ”项目符号；每项必须能在模板一行内排完（版面单位 ≤34），不要写成需要换行的长句。
- `experiment_method_points`：按“实验设计→平台与基线→数据与变量”从整体到细节分层组织，体现层次感，标签固定从这三组用语中选取，见 content-schema.md。
- `experiment_result_summary`（实验总结）：一句适合人读的完整表述，说清楚这组实验总体证明了什么，可以比分点略长（最多约 2 行）；不含冒号标签，加粗的“实验总结：”前缀由 `build_deck.py` 自动添加。
- `experiment_result_points`（关键指标）：2–3 项，写成“具体指标名称：结果表现”，标签必须是被测的具体指标（吞吐量、延迟、显存占用、准确率等），不得写“关键数据”这类空泛词；结果表现必须带数字或百分比；渲染时统一放在“关键指标：”小标题下，每项自动加“• ”项目符号；每项必须能在模板一行内排完（版面单位 ≤34）。不要设置 `experiment_result_header`，模板里这一区域已经有固定的“实验结果”标签，不需要在内容里重复。
- 实验图会和实验结果文字动态重排：图片实际渲染得越矮（比如偏宽的柱状图），下方文字能拿到的高度就越多；这是为了把图片周围的留白让给文字，不需要在 spec 里手工处理，只要内容遵守上面的版面上限即可。
- `takeaway`：至少 70 个中文字符，聚焦先进性（相比现有方案/基线的具体优势）、成熟度（原型/小规模验证/可规模化落地）、借鉴意义（对当前系统的具体指导）三点，不再要求复述机制或实验细节。
- 技术细节和实验结果都要照顾人类读者：宁可多写几个字把话说完整、说自然，也不要为了塞进版面预算而写成生硬的短语拼接。

技术细节区根据论文或外部数据源的实际内容选 1–2 张图：

- 一张图时，按原图长宽比自动选择“上图下文”或“左图右文”，图片与技术要点共同填满左侧区域。
- 两张图时，必须横向排列，并按两张原图的长宽比分配宽度；两张图应分别说明互补机制，不得重复使用同一图片。
- 图片完整性优先于填满固定占位框。不得拉伸，不得为适配模板而裁掉架构边界、图例、坐标轴、标签或关键对比项。

使用：

```powershell
python scripts/extract_figure.py page --pdf paper.pdf --page 5 --dpi 300 --out page5.png
python scripts/extract_figure.py crop --pdf paper.pdf --page 5 --dpi 300 --bbox-pct 0.08,0.18,0.92,0.55 --out figure.png
```

裁图后必须在原始分辨率下复核：图框、图例、轴标、箭头、节点名称和必要图注完整可读；裁掉页眉页脚、页码、相邻正文段落和无关留白。把每张技术图和实验图的复核结果写入 `figure_quality_checks`；无法通过完整性、干净裁切和清晰度检查的图片不得进入预览或 PPT。

按 [references/content-schema.md](references/content-schema.md) 编写 UTF-8 `spec.json`。首次预览时设置：

```json
{
  "review": {
    "status": "draft",
    "version": 1,
    "review_note": "首次内容预览"
  }
}
```

### 4. 校验并生成预览

```powershell
python scripts/validate_spec.py --spec .\spec.json --phase preview
python scripts/render_preview.py --spec .\spec.json --out-dir .\preview --format both
```

向用户展示 `.md` 和 `.html` 文件。预览必须包含完整页面顺序、技术阶段与后续页面的关系、全部技术页内容、图片、引用、高校与教师课题和技术洞察观点，不能只给标题大纲。

### 5. 等待确认并迭代

在用户明确表示“确认”“可以生成”或等价指令前，停止在预览阶段，不运行 `build_deck.py`。

收到反馈后：

1. 修改同一份 `spec.json`
2. `review.version` 加 1
3. 把改动摘要写入 `review.review_note`
4. 重新校验并同时生成 Markdown/HTML 预览
5. 再次交付预览等待确认

用户明确确认后，把 `review.status` 改为 `approved`，保留最终版本号和确认说明。

### 6. 生成 PPT

`assets/template.pptx` 是唯一视觉真源。最终 `.pptx` 只能由本 skill 的
`scripts/build_deck.py` 生成；不得另写 JavaScript/Python 脚本从空白演示文稿重建页面，
不得调用 `Presentation.create`，不得用近似色值、线条或卡片“复刻”模板。

所有内容页必须从模板中的既有页面复制并保留以下结构：

- 原页面尺寸、母版、版式、主题和页脚
- 红色标题及其字号、位置和字重
- 单项洞察页的虚线圆角双栏框
- 灰色“技术背景”信息带
- 底部灰色“洞察启示/洞察观点”信息带
- 模板中的品牌标识、页码和安全级别信息

趋势、学术资源和技术洞察观点页也必须复制单项洞察模板页后改写内容，不能先建立空白页再加
浅色卡片。允许调整双栏内部的内容排布，但不得删除上述结构后另行绘制。

```powershell
python scripts/validate_spec.py --spec .\spec.json --phase build
python scripts/build_deck.py --spec .\spec.json --out .\outputs\tech-insight.pptx
PowerShell -File scripts/check_ppt_text_overflow.ps1 -Deck .\outputs\tech-insight.pptx
python scripts/validate_template_fidelity.py --template .\assets\template.pptx --deck .\outputs\tech-insight.pptx --spec .\spec.json
```

`build_deck.py` 会拒绝未确认的 spec。技术趋势、学术资源和技术洞察观点三页必须使用纯白背景、浅色卡片，并与单项洞察页统一使用微软雅黑和固定色板：

- 标题：`#CC0000`
- 主色：`#1B3A6B`
- 辅色：`#00C9C8`
- 高亮：`#FF6B35`
- 正文：`#333333`
- 背景：`#FFFFFF`

禁止在这三页使用机器人、风景等母版背景大图，也禁止使用大面积深蓝、深棕或橙色底块。趋势页底部使用与单项洞察页“洞察启示”相同的灰底、红色标签栏，标签写“洞察观点”。

### 7. 视觉检查

将 PPT 转为 PDF 或逐页图片，检查所有页面：

- 先把模板第 4 页与任一生成的单项洞察页并排查看；标题、双栏框、背景带、观点带和页脚必须来自同一模板结构
- 成品页面尺寸、母版数量、版式名称和关键形状通过 `validate_template_fidelity.py`
- 趋势页每个阶段与一个代表性进展逐行对应，并包含真实图片和可点击来源
- 趋势页不出现研究过程里的分类术语，底部只有一句“洞察观点”
- 技术趋势、学术资源和技术洞察观点三页均为白底浅色系，无母版背景大图
- 每个技术页右上角出现窄条阶段标签，且 `stage_id` 正确；标签框较窄、灰色边框，位于页面右上角，且不挡住标题
- 技术背景是连续自然段，不显示“现状：”“痛点：”“问题：”等字段标签；行文从当前约束自然引出痛点和课题问题
- 技术细节区只有 1–2 张互补图片；单图自动展开，双图横向排列且按原图比例分配宽度；单张竖图采用左图右文时，右侧文字整体垂直居中，不贴顶对齐
- 技术细节是“核心思想（一句适合人读的完整表述）+ 关键技术（2–3 个加粗名称分点，带“• ”符号）”，文字读起来自然顺畅，不是电报式短语堆砌
- 实验方法按“实验设计→平台与基线→数据与变量”分层展示，能看出从整体到细节的层次
- 实验结果是“实验总结（一句适合人读的完整表述）+ 关键指标（2–3 个加粗指标名分点，带“• ”符号）”，不出现“关键数据”“实验结果”等多余字样，文字读起来自然顺畅
- 实验结果文字不得超出双栏卡片的下边框；实验图比预留空间矮时，多出的空白应该已经让给了下方文字，不应同时出现“图片周围一大片空白”和“文字顶破边框”
- 洞察摘要页“技术脉络”下的方向卡片使用灰色边框，与单项洞察页右上角的技术脉络标签风格一致
- 技术背景、技术细节、实验方法与结果、洞察启示通过内容预算校验和 PowerPoint 实际边界测量；不得裁切、溢出或静默缩字
- 每页洞察启示至少含 70 个中文字符，聚焦先进性、成熟度与借鉴意义三点，不啰嗦、不复述机制
- 论文图片不变形、不缺失；架构边界、图例、坐标轴、标签和关键对比项完整可读
- 图片不包含页眉页脚、页码、相邻正文段落或与当前论点无关的区域
- 学术资源页包含高校、实验室、教师、研究方向与代表课题，主页和课题链接可点击
- 技术洞察观点页使用主题化小标题，是最后一张内容页，建议可执行
- 页面不出现“研究集群”“证据缺口”“阅读策略”“Now / Next / Watch”“置信度”等框架化措辞
- 全局字体、标题、正文、颜色和留白一致
- 无 `xxx`、占位符、空表格行或未确认状态

至少完成一次修正并复检；仍有用户可见问题时继续修正。

## 脚本职责

- `scripts/validate_spec.py`：校验结构、阶段关联、图片与确认状态
- `scripts/render_preview.py`：从同一 spec 生成 Markdown/HTML 内容预览
- `scripts/build_deck.py`：从已确认 spec 生成统一样式 PPT
- `scripts/check_ppt_text_overflow.ps1`：在 PowerPoint 中测量指定区域文字边界，拒绝裁切或溢出
- `scripts/validate_template_fidelity.py`：拒绝从空白演示文稿重画、母版丢失或关键模板结构缺失的成品
- `scripts/extract_figure.py`：从论文 PDF 渲染并裁剪真实图片
- `scripts/inspect_template.py`：模板变更时检查形状 ID

## 不可违反

1. 未获用户明确确认，不生成 PPT。
2. 趋势页先于摘要和单项技术页。
3. 趋势页必须包含 3–4 个技术阶段；每个阶段都有一个代表性进展、有效来源链接和真实图片。
4. 每个方向和技术页必须链接到有效 `stage_id`。
5. 趋势页不暴露研究方法标签，底部只写一句洞察观点。
6. 一篇论文只占一页；每页必须有真实架构图和真实实验图。
7. 学术资源页位于全部技术页之后。
8. 技术洞察观点是致谢前最后一页。
9. 不臆造论文、数字、引用、厂商动作、GitHub Stars 或时间信息。
10. 英文论文标题和技术术语保留英文，分析与建议使用中文。
11. 技术背景必须用连续自然段呈现现状、痛点和课题问题，页面不得显示内部字段标签。
12. 技术细节区只允许 1–2 张图；两张图必须横向排列、内容互补且不重复。
13. 截图必须通过完整性、干净裁切和清晰度检查；残缺图、低清图和带无关正文段落的截图不得使用。
14. 最终 PPT 只能由 `scripts/build_deck.py` 写出；其他演示工具只允许只读导入、渲染和检查，不得重新导出为最终文件。
15. 禁止 `Presentation.create`、空白页生成和模板近似重绘；模板一致性校验失败时必须回到 spec 或 `build_deck.py` 修复。
16. 技术背景、技术细节、实验方法与结果、洞察启示不得超出各自模板区域；超量时先改写文案，不得自动缩小模板字号。
17. 单项技术页的洞察启示至少包含 70 个中文字符，且必须同时说清先进性、成熟度和借鉴意义三点，不得复述机制或实验细节凑字数。
18. 技术细节必须是“`tech_detail_summary` 核心思想一句话 + `tech_detail_points` 2–3 个关键技术分点”，关键技术名称必须真实、具体并自动加粗；不得用“机制/设计/边界”等空泛标签替代技术名称；两部分文字都要写成适合人读的自然中文，不得堆砌电报式短语。
19. 实验方法必须按“实验设计→平台与基线→数据与变量”分层组织；实验结果必须是“`experiment_result_summary` 实验总结一句话 + `experiment_result_points` 2–3 个关键指标分点”，每项标签必须是具体指标名称且带数字，不得使用“关键数据”等空泛词，也不得设置 `experiment_result_header` 重复“实验结果”字样。
20. 技术细节区单张竖图采用左图右文布局时，右侧文字必须整体垂直居中。
21. 每个技术页右上角的技术脉络标签必须窄、灰色边框，几何上不得与标题框重叠。
22. `tech_detail_points`、`experiment_result_points` 每个分点都独占一行，必须能在模板一行内排完（版面单位 ≤34）；图片比预留空间矮时可以把多余空白动态让给下方文字，但不能替代分点长度控制——分点本身写太长仍会顶破卡片下边框。
