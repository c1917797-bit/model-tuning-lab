## Formal graph contracts and honest readiness

Freeze the final common configuration before extending a pilot. Read the actual
source and hash it: a shared-prefix workload can still have prefix caching OFF,
and a concurrent client can still use a different native graph/allocation path.
Carry final batch tails, context, graph mode and task limits into the provider,
kernel and independent consumer. Do not silently replace the formal graph control
with eager merely because the pilot was eager.

For graph ports, prepare fixed workspace and stable input bindings before capture,
then verify actual capture and replay with changing requests. A software slot-table
test is not a graph test. Charge every allocation, intermediate and capture lifetime

scoped unsupported result, not an invented measured OOM.

cannot establish target-image geometry or a fully installed native backend.

pins. Report completed real entry tests, not only delivered code or an agent's
ready label.

## Pilot domains, real memory savings and repair readiness

Keep a domain ledger from the pilot through final acceptance: actual context
length, batch/tail shapes, request retirement and reuse, prefill/decode mixing,
graph mode and task output limit. A B1-only cache that closes the whole engine
at finish is not a C16 provider. Increasing CLI concurrency or max_tokens does
not implement missing ownership, capacity or lifecycle semantics. Label this
as unfinished adaptation, not evidence against the paper; prepare its allocator,
provider and final-task consumer while the pilot runs.

Distinguish IO savings from HBM savings. Suppressing an unused dense decode
write can save writes/launches, but a retained preallocated dense slab still
occupies memory. Returning logical blocks to a free queue does not shrink that
allocation. A compact-cache port must connect its actual Spec/manager,
Ascend allocation/backend layout, prefill workspace and per-request slot/epoch
lifetime. Verify actual allocated storage and all legitimate readers/writers;
do not free a request's other live cache groups or storage shared with GDN.
Capacity arithmetic is conditional on residency, sharing, dtype and alignment,
not an observed OOM. Client concurrency alone does not prove simultaneous
cache residency; shared prompt tokens alone do not prove prefix caching ON.

including cache-write notifications, transfer/fence semantics and downstream
consumers. Preserve dense/prefill behavior and exactly-once candidate append.
Reject unsupported mixed/lifecycle paths; never fall back to stale dense cache.

speedup forecast or permission to replace final C16 validation with B1.

## Trigger, authority and scope

Apply after any failed paper preparation, native numerical, model, performance
or task-accuracy stage, before changing implementation or moving to another
paper. Practice source: the user's Oct9 instructions to diagnose, repair
adaptation defects and use that diagnosis to choose the next action.

A failed run and a failed method are different claims. Classify the observed
failure AND record whether its cause is proved, suspected or unknown. Do not
force a binary implementation-versus-method verdict when evidence is missing.
This rule grants no device permission and never resets a fixed paper cutoff.

## Required causal record

Preserve the original terminal envelope, exact source/manifest and environment,
full argv, first exception, original inputs and nullable before/after tensors,
actual coverage and untouched partial results, cleanup and resource ownership.
Record the failed gate, classification, causal evidence, alternative explanations,
decision scope, chosen repair or diagnostic, unchanged acceptance thresholds,
new experiment/output identity, owner, remaining budget and successor consumer.

A top-level command exit and a child-suite exit must both be recorded. Partial
passing cases do not make an incomplete aggregate pass. Missing evidence is
explicitly missing, never reconstructed as an original receipt.

When a failed parent never emitted its final result index or post-input identity
check, child success cannot fill that gap implicitly. A recovery consumer must
explicitly qualify the original successful-child receipts and perform the missing
checks under a new recovery schema. Do not change the old FAILED/exit1 into PASS,
fabricate its absent result, or route a recovered component through an unchanged
legacy consumer that requires whole-parent success.

## Repair loop, not stop-at-diagnosis

1. Isolate and preserve the failed scope and any valid predecessor artifacts.
2. Choose ONE evidenced repair or discriminating diagnostic. Reuse a correct
   native primitive; don't rewrite unrelated operators or patch a refuted finding.
3. Freeze a new source identity/experiment and output root; retain failed source
   in Git and large originals outside Git. Never lower thresholds, fabricate PASS,
   exclude observed failures retroactively or retry unchanged deterministic errors.
4. Run complete affected software/CLI/same-image preflight before scarce cards.
   Exercise reused modules and their transitive imports in a fresh process using
   the exact guest entrypoint and source-qualified names. Read-only mounts or
   AST/mock-only tests do not prove import closure; reject foreign cached modules
   and preserve failure before any device initialization.
5. Run the relevant complete NPU numerical/state/lifecycle/graph gate.
6. Only after that passes advance to paired whole-model performance and tasks.
7. Update the causal record: repaired-but-unverified, verified repair, still
   failing, or unresolved. A repair commit is not an NPU or deployment PASS.

A repairable adaptation defect is an action item, not grounds to abandon a
paper and call it ineffective. When the fixed timebox ends, close only the
unfinished implementation as failed/inconclusive with exact missing evidence;
keep the prepared repair for a later explicitly selected continuation. Advancing
the queue does not broaden the negative verdict or reset its deadline.
