# Portfolio preparation and serialized device admission

Use this for the user-authorized multi-paper Ascend portfolio, not unrelated
single-change work. Current hardware is physical NPU4–7; NPU0–3 is protected.
Latest user direction: preparation runs in parallel; papers use the four-card
validation lane serially. Keep project-specific deadlines in workstream records,
not a moving universal deadline in this skill.

## Prepare breadth without fabricating readiness

Maintain one indexed backlog for every in-scope paper. Distinguish:
source/mechanism audited -> implementable packet -> numerical ready ->
model/lifecycle ready -> measured -> final acceptance. A reviewed paper,
helper/mock PASS, plan CLI, build/Meta receipt or token sample cannot promote
another stage. Name the actual owner and missing artifact, including final
task-runner identity when unresolved.

With limited agent slots, assign rolling mechanism groups. Give each preparer
a concrete algorithm-specific implementation gap and separate draft scope;
rotate finished agents to the next unresolved paper instead of letting all
slots stay on the active paper's tooling. Shared repo/device/Git writes remain
with MAIN. Transfer the complete patch, actual tests and source identities,
not only prose or an imagined future command. An agent's software report still
requires MAIN review before shared application/admission.

Every numerical-ready packet binds the author's mechanism or explicitly named
Ascend adaptation, opt-in plugin, independent oracle, relevant complete matrix,
true shapes/batches, native source/artifact identities, actual CLI/mounts,
nonoverwrite outputs, summed CPU/ordinary-RAM/disk budget, own-only cleanup
and a real successor consumer. Model-ready additionally binds allocator,
request-slot/reuse/mixed/graph behavior and paired dense measurement entry.
Reuse open-source operators and infrastructure, not another algorithm's PASS.

## Execute the correct queue

### Rolling slot refill and one-entrypoint handoff

For the explicitly authorized parallel portfolio, reconcile actual live agent
handles with the indexed backlog at each delivery or terminal event. A source
group name in a handoff is not proof that its agent is still running. Refill a
finished slot with the next actionable preparation gap; do not wait for that
packet's NPU result or let all preparers drift back onto the active paper.
An active preparer hands off a completed packet by message and continues its
assigned successor. If it has already terminated, MAIN uses a follow-up or a
replacement agent within the currently available concurrency limit. More Git
branches do not create more agent slots; use distinct draft scopes and respect
the repository worktree budget. No idle loops or dummy jobs count as progress.

Each delivery includes the complete patch, immutable source identities, actual
device-independent tests, one aggregate validation entrypoint, fresh-resource
discovery requirements, complete case coverage, downstream model/performance
consumers and pending prerequisites. MAIN reviews and integrates the packet,
then queues its highest-value unrun device gate. Discover known source/schema/
CLI/mount/resource-report mismatches before device reservation. Prepared
commands do not make archived resource facts fresh or guarantee numerical PASS.
At device admission, bind the actual physical mapping, host/cgroup budgets and
ownership once for the bounded matrix, monitor changes, preserve first failure
and already-valid child evidence, and release only the owned lease. Device
jobs remain serialized across papers; no preparer independently starts a
container or reserves cards just because it finishes a packet.

When a gap is genuinely blocked or out of scope, record its concrete dependency
and continue another actionable paper. Missing draft inheritance is a source
gap, not grounds to repeat broad directory searches or declare algorithm no-go.
Do not hold a preparation slot awaiting MAIN when other assigned work remains.

MAIN selects the highest-value ready successor using remaining time and
current evidence, rather than waiting for every paper to be ready. Cross-paper
NPU work is serialized for this portfolio. Within-paper preregistered disjoint
numerical shards may share the authorized four cards if their joint budget
fits; TP4/full-model/profile/formal performance is exclusive. All papers keep
a fair same-stack/common-optimization dense comparison.

Fresh process/HBM/AICore mapping and host/cgroup resources govern admission.
An idle card does not imply sufficient ordinary host RAM; HugeTLB and protected
workloads are not resources to reclaim. Declared devices alone do not prove
occupation. Record real idle time and its blocker; dummy jobs do not improve
throughput of evidence.

Environmental stop, observer/schema failure, numeric failure, valid regression
and insufficient applicability evidence are different outcomes. Preserve the
first real terminal/raw failure; fix only a proved seam, never fabricate a
failed-time snapshot or lower a tensor gate. External command churn is not
external identity churn: inspect what the actual predicate compares. A test
aborted before algorithm execution cannot establish paper-wide failure.

Keep the actual per-paper clock and portfolio cutoff fixed. Preparation does
not reset a running clock. At each terminal/checkpoint, reconcile short work
with mechanism -> native correctness -> paired E2E -> final task quality,
release/retain owned resources, then admit the next ready gate promptly.
Do not hold idle cards for report prose or pursue unrelated operator tuning.

For native interfaces with a no-device dispatcher/schema path, use that real
installed path before allocating the long device matrix. Public API families
and mocked helper tests do not establish the deployed output/workspace
signature. In the pinned0.23/TorchNPU2.10 FlashInfer preparation,47 software
tests passed but an actual no-device probe showed old-FIA.out uses Tensor[]
out, not separate attention_out/softmax_lse keywords. Preserve the failed
version and actual schema; repair a source-supported successor, not thresholds
or a paper-wide conclusion. Byte-exact installed model-source snapshots remain
usable source evidence when an unrelated later schema assertion fails, while
still providing no NPU/model/performance authority. See current workstream
FLASHINFER_ABI_PREFLIGHT_20261007.md.

For relocated preparation packets, execute the REAL dependency import under
the exact entry cwd and clean PYTHONPATH before device reservation. AST parse,
default-OFF help, SHA closure and mocked imports do not exercise package search
paths. Resolve canonical plugin dependencies explicitly and hash-bind them;
never assume an inherited helper's sys.path side effect. Preserve an actual
entry/import failure separately from a numerical no-go, even after canary PASS.
See H8_FULL_IMPORT_FAILURE_20261007.md for a four-shard, zero-numeric-case miss.

Call a phase physically no-device only when actual owned inspect/namespace
proves Devices=[] and no exposed compute/control device nodes. Empty process
FDs and is_initialized=False establish no-init, not absent devices. For staged
ABI then NPU work, bind both owned CIDs, sequential aggregate resources, one
unchanged phase deadline and each exact stop-retain/terminal receipt. Never
promote the CPU schema phase, exposed-device declaration or canary to numerics.

In this host's bounded Python controller, Docker's Go CLI needs its own
address-space wrapper even for read-only ps/inspect diagnostics. MA0e65 failed
Go reservation under the inherited256MiB soft AS limit; the changed Docker-only
AS restoration passed MA0e69. Keep the parent plus CLI RSS and cgroup budget;
do not make the whole controller unbounded or count that diagnostic as numerics.
