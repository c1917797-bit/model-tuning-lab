# Portfolio preparation and serialized device admission

Use this for the user-authorized multi-paper Ascend portfolio, not unrelated
single-change work. Current hardware is physical NPU4–7; NPU0–3 is protected.
Latest user direction: preparation runs in parallel; papers use the four-card
validation lane serially. Keep project-specific deadlines in workstream records,
not a moving universal deadline in this skill.

## Prepare breadth without fabricating readiness

Maintain one indexed backlog for every in-scope paper. Distinguish:
source/mechanism audited -> implementable packet -> numerical ready ->
model/lifecycle ready -> measured -> final acceptance. A reviewed paper,
helper/mock PASS, plan CLI, build/Meta receipt or token sample cannot promote
another stage. Name the actual owner and missing artifact, including final
task-runner identity when unresolved.

With limited agent slots, assign rolling mechanism groups. Give each preparer
a concrete algorithm-specific implementation gap and separate draft scope;
rotate finished agents to the next unresolved paper instead of letting all
slots stay on the active paper's tooling. Shared repo/device/Git writes remain
with MAIN. Transfer the complete patch, actual tests and source identities,
not only prose or an imagined future command. An agent's software report still
requires MAIN review before shared application/admission.

Every numerical-ready packet binds the author's mechanism or explicitly named
Ascend adaptation, opt-in plugin, independent oracle, relevant complete matrix,
true shapes/batches, native source/artifact identities, actual CLI/mounts,
nonoverwrite outputs, summed CPU/ordinary-RAM/disk budget, own-only cleanup
and a real successor consumer. Model-ready additionally binds allocator,
request-slot/reuse/mixed/graph behavior and paired dense measurement entry.
Reuse open-source operators and infrastructure, not another algorithm's PASS.

## Execute the correct queue

MAIN selects the highest-value ready successor using remaining time and
current evidence, rather than waiting for every paper to be ready. Cross-paper
NPU work is serialized for this portfolio. Within-paper preregistered disjoint
numerical shards may share the authorized four cards if their joint budget
fits; TP4/full-model/profile/formal performance is exclusive. All papers keep
a fair same-stack/common-optimization dense comparison.

Fresh process/HBM/AICore mapping and host/cgroup resources govern admission.
An idle card does not imply sufficient ordinary host RAM; HugeTLB and protected
workloads are not resources to reclaim. Declared devices alone do not prove
occupation. Record real idle time and its blocker; dummy jobs do not improve
throughput of evidence.

Environmental stop, observer/schema failure, numeric failure, valid regression
and insufficient applicability evidence are different outcomes. Preserve the
first real terminal/raw failure; fix only a proved seam, never fabricate a
failed-time snapshot or lower a tensor gate. External command churn is not
external identity churn: inspect what the actual predicate compares. A test
aborted before algorithm execution cannot establish paper-wide failure.

Keep the actual per-paper clock and portfolio cutoff fixed. Preparation does
not reset a running clock. At each terminal/checkpoint, reconcile short work
with mechanism -> native correctness -> paired E2E -> final task quality,
release/retain owned resources, then admit the next ready gate promptly.
Do not hold idle cards for report prose or pursue unrelated operator tuning.
