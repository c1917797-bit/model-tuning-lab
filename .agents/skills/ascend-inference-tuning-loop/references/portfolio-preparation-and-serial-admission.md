## Prepare breadth without fabricating readiness

Maintain one indexed backlog for every in-scope paper. Distinguish:
source/mechanism audited -> implementable packet -> numerical ready ->
model/lifecycle ready -> measured -> final acceptance. A reviewed paper,
helper/mock PASS, plan CLI, build/Meta receipt or token sample cannot promote
another stage. Name the actual owner and missing artifact, including final
task-runner identity when unresolved.

With limited agent slots, assign rolling mechanism groups. Give each preparer
a concrete algorithm-specific implementation gap and separate draft scope;
rotate finished agents to the next unresolved paper instead of letting all
slots stay on the active paper's tooling. Shared repo/device/Git writes remain
with MAIN. Transfer the complete patch, actual tests and source identities,
not only prose or an imagined future command. An agent's software report still
requires MAIN review before shared application/admission.

Every numerical-ready packet binds the author's mechanism or explicitly named
Ascend adaptation, opt-in plugin, independent oracle, relevant complete matrix,
true shapes/batches, native source/artifact identities, actual CLI/mounts,
nonoverwrite outputs, summed CPU/ordinary-RAM/disk budget, own-only cleanup
and a real successor consumer. Model-ready additionally binds allocator,
request-slot/reuse/mixed/graph behavior and paired dense measurement entry.
Reuse open-source operators and infrastructure, not another algorithm's PASS.

## Execute the correct queue

### Rolling slot refill and one-entrypoint handoff

For the explicitly authorized parallel portfolio, reconcile actual live agent
handles with the indexed backlog at each delivery or terminal event. A source
group name in a handoff is not proof that its agent is still running. Refill a
finished slot with the next actionable preparation gap; do not wait for that
packet's NPU result or let all preparers drift back onto the active paper.
An active preparer hands off a completed packet by message and continues its
assigned successor. If it has already terminated, MAIN uses a follow-up or a
replacement agent within the currently available concurrency limit. More Git
branches do not create more agent slots; use distinct draft scopes and respect
the repository worktree budget. No idle loops or dummy jobs count as progress.

Prioritize ready stages by expected advancement toward acceptance per elapsed
hour, not by paper count, novelty or occupancy. Include launch, warmup, oracle,
transfer, cleanup and consumer costs when estimating that hour. Reserve time
for matched E2E and final tasks inside the unchanged portfolio deadline.
An estimate is a scheduling hypothesis; update it from actual completions.
Track executable-ready count, per-card useful compute time, verified gate
completions, terminal-to-dispatch delay, and idle intervals by cause (missing
packet, host resource admission, diagnosis, transfer or safe handoff).
At each terminal or delivery, reconcile these against the medium/long goal.
The target is to remove avoidable gaps and sustain a ready successor, not an
unmeasured promise of zero idle time or an accepted technique guaranteed by
process discipline. Safety and comparable exclusive timing remain mandatory.

Each delivery includes the complete patch, immutable source identities, actual
device-independent tests, one aggregate validation entrypoint, fresh-resource
discovery requirements, complete case coverage, downstream model/performance
consumers and pending prerequisites. MAIN reviews and integrates the packet,
then queues its highest-value unrun device gate. Discover known source/schema/
CLI/mount/resource-report mismatches before device reservation. Prepared
commands do not make archived resource facts fresh or guarantee numerical PASS.

ownership once for the bounded matrix, monitor changes, preserve first failure
and already-valid child evidence, and release only the owned lease. Device
jobs use MAIN-coordinated disjoint admission only when the actual controller
and aggregate budget support it; no preparer independently starts a container
or reserves cards just because it finishes a packet.

When a gap is genuinely blocked or out of scope, record its concrete dependency
and continue another actionable paper. Missing draft inheritance is a source
gap, not grounds to repeat broad directory searches or declare algorithm no-go.
Do not hold a preparation slot awaiting MAIN when other assigned work remains.

current evidence, rather than waiting for every paper to be ready. Independent
cross-paper or within-paper numerical/preparation shards may share disjoint

same-stack/common-optimization dense comparison.

## Native configuration checks before device admission

Parser success is not engine-configuration success. Exercise the installed
configuration constructors with the actual checkpoint and intended flags
before a device lease whenever that path is genuinely device-free. Include
batch/model-length inequalities, model capabilities, chunking/prefix/mamba
interactions, runtime role paths and mounted dependency imports. Keep a
negative regression from the actual rejected configuration; mocked parsers
and a large source-test count cannot promote the native gate.

Cover the real constructor, including required InitVars and the installed
default factory, not an extracted validator alone. A CPU decoder assumption
must be labeled as an assumption and independently checked against the real
ModelConfig at the hardware boundary; never turn a default into checkpoint
evidence.

Before declaring an executable image-preflight ticket, resolve every actual
mount source, not just plugin source hashes. Check the frozen checkpoint,
calibration input index and all input bytes, nested receipt dependencies,
guest destinations and prospective output parent. If an unchanged input lives
at a different verified host path, bind that exact host path read-only to the
declared guest path in a new experiment; do not create a guessed host alias or
change the input silently. Report the exact missing source/destination before
Docker create. Retain and regression-test the real failed path. A source-closure
PASS is not data/mount-closure PASS.

If a constructor genuinely requires hardware, separate and report the exact
CPU-validated subset. Run the remaining native configuration check after the
bounded canary but before weights or the long matrix; do not stub the platform
or advertise complete no-card validation. A configuration adaptation is a
new frozen experiment, and observed token scheduling must still match the
original numerical coverage. Source reasoning alone does not prove one full
prefill frame was executed.

Keep long, device-independent numerical consumers out of the device lease.
Seal complete raw capture and lifecycle indices, verify exact own stop-retain
and resource release, then adjudicate immutable raw in a separately budgeted
CPU stage. Another ready paper can use the serial NPU lane meanwhile. Preserve
all raw and check the larger retention budget before acquisition. A local
release-order regression is not an observed cross-paper handoff.

## Phase-DAG continuation and the serial device lane

Queue executable STAGES, not whole papers. Each paper keeps one owner and its
own source-frozen DAG/first-fault artifacts; every node names predecessors with
actual accepted Refs, entry/consumer, new output root, cost/budget, resources,
deadline and next-action policy. Separate an implementation/source revision
from an execution attempt. Pending, stage-ready, running, result-pending,
passed, failed and blocked states must not borrow one another's authority.

Device-free source/oracle/adapter work runs across papers in distinct edit
scopes within agent and joint host budgets. MAIN is the only device dispatcher.
For the current serial mode, admit one complete bounded device stage at a time;
a numerical full matrix or a matched dense/candidate pair is an indivisible
stage. Freeze its inputs and source until actual termination. A delivered patch
is only preparation, not an NPU ticket.

At the terminal event, preserve the actual outcome, validate the relevant
consumer and verify own-only release. Unconfirmed termination/release blocks
new device admission; retain UNKNOWN and recover exact ownership instead of
relaunching. Once resource release is proved, a device-independent result
adjudication may continue with its paper owner while MAIN dispatches another
ready stage. If a failed paper needs device-free repair or preparation, remove
it from CURRENT and the ready device lane; its owner continues the paper DAG
off-device. Admit another paper whose actual prerequisites pass, without waiting
for the failed paper's repair, report or Git publication. If none is ready,
record ready-count zero and refill an independent preparation lane immediately.
A written queue rule is not evidence of an actual handoff or gap-free usage.
PASS unlocks only the actual successors whose prerequisites it satisfies.
A proved implementation defect opens a bounded repair -> regression
-> relevant smoke -> requeue edge. Unknown causes open a discriminating
diagnostic edge; valid no-gain closes only the measured configuration. Failure
does not silently cancel the paper or grant its downstream performance gate.

Give each completion an explicit continuation: paper owner, next node, evidence
Refs, missing edges and unchanged remaining time. Idle/finished owners receive
a follow-up task within available agent slots; running owners receive the
result at their message boundary. Do not create a new user-owned chat per stage.
Maintain a reviewed NEXT ticket and independent BACKUP during CURRENT, with
ready counts by gate rather than paper count. Normal event-driven handoff is
immediate when prerequisites/ownership permit; periodic audit is recovery
fallback, not a15-minute dispatch delay by design.

This graph maximizes useful gate progression, not artificial occupancy.
Performance controls cannot interleave with other NPU activity. No automatic
clock renewal, missing-ref promotion or unbounded repair cycle; use the same
causal classification and fixed acceptance deadline.

## Runtime factory coverage and failure diagnostics before assertions

A mock dictionary prefilled with keys does not validate a real module factory.
Enumerate every bootstrap/worker consumer key and callable signature, compare
with the actual source-qualified factory output, and run a producer-to-consumer
integration test before the next NPU attempt. Repair common missing roles once,
not one KeyError per device run. Keep compiler/HAL imports on the initialized
NPU side when they cannot safely run in Devices[]; do not fake hardware access.

Canaries must publish bounded actual arithmetic values, getter result type/name,
raw representation and source identity before assertions. Separate arithmetic
failure from ABI/format serialization failure; a combined assertion without raw
values cannot establish which condition failed. Reuse the deployed version's
verified enum adapter, never coerce an arbitrary object merely to pass.

On such an implementation failure, stop-retain only the exact owned workload,
verify Pid0/noExec/noOOM and device release, and return that paper to preparation.
Run another actually ready paper immediately; if none is ready, report the real
queue gap and fix preparation. Passed immutable prerequisites may be reused only
with exact source/input/output bindings and independent consumption; a failed
whole run must not be relabelled successful because its earlier CPU stage passed.
