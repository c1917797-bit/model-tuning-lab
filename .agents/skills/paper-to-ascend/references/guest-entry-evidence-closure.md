# Guest-entry evidence closure

Use this reference when a bound source or software prototype passes but the real guest entry still fails. The existing [failure attribution](../../ascend-inference-tuning-loop/references/failure-root-cause-and-next-action.md) and [matched validation DAG](../../ascend-inference-tuning-loop/references/paper-validation-dag-and-matched-controls.md) remain authoritative. These are execution gaps in applying those rules, not permission to add a second validation framework.

## Decide the next action from the evidence

| Evidence available | Allowed conclusion | Next action |
| --- | --- | --- |
| SOURCE/COMMANDS bound, or host/pure controls pass | Preparation only; guest readiness remains unproved | Reopen the exact real CLI and guest reader contract, not a synthetic success path. |
| Source admission, name, import, or guest readset fails | Current integration is NOT_READY; no paper-level no-go | Repair the first proved contract at its actual caller/callee boundary; retain the failure. |
| Real short8 independent NPU scope passes | Only its numerical/state scope passed | Preserve the proof and check the separately required long-run, paired performance, and task-accuracy gates. |
| Valid paired model measurements show no gain | No gain for that frozen configuration | Attribute measured overhead before deciding whether another configuration or implementation is justified. |
| The requested full pair plus cleanup cannot fit its authorized window | Do not dispatch that pair | Judge a separately authorized independent stage against its own frozen phase, cleanup and scope. Do not split or shrink the formal pair to evade its gate, reset the start, or treat a partial pair as equivalent. |

## Close the real guest contract

- Source protocol and typed Ref3 roles must match the consuming API. A host file's existence does not prove its guest path, bytes, mount mode, or lifetime.
- Follow the actual transitive reader graph. A window's four direct refs do not close guest validation when rendering calls admission again. Do not mark the short8 reports host-only without checking that real consumer.
- Include directory/glob/negative-existence observations when the actual reader branches on them. File coverage alone cannot reproduce those branches. Prefer a supported, bounded evidence view over an unbounded per-file argv/mount expansion; measure the real argv and environment against ARG_MAX and validate every generated name role.
- Typed trees and terminal views are evidence-visibility adapters. Their pure-control timings are not algorithm throughput or NPU performance evidence, and do not substitute for fresh guest collection or the original full-SHA/tensor consumer. Explicit false readiness and qualification fields remain false until the real stages run.
- Consuming verified module bytes is insufficient if a dependent module later imports a different cached or path-resolved object. Bind the dependent import to the verified module identity in the actual loader. Check transitive and delayed imports with deterministic field/order handling; do not replace failed imports with success fixtures.

## Keep control work bounded

Use the original low-overhead need-first control at the required boundary; whole-chain tracing must not become the default evidence mechanism. Source-only work, loading, compilation, and data movement must be reported separately from effective NPU validation. Do not manufacture utilization by holding devices.

A timed-out operation is followed to its own persisted terminal and release state. Do not start a replacement operation to conceal uncertainty. After a proved code/control change, a new bounded attempt gets a new output directory and retains its predecessor failure.

For this collaboration API, send_message delivers a message without starting a new turn. Reassign an idle/completed preparation agent with followup_task; send only a new useful node, not the already completed work. This is a coordination contract, not authorization for devices or external messages.
