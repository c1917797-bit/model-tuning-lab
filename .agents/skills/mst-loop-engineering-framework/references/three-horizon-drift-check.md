# Three-horizon drift check

Use this when a substantial task spans sessions or a long experiment; ordinary
one-step tasks do not need three separate goal documents.

Keep a concise goal map in the workstream state:

- **Long term:** the durable user outcome and final acceptance boundary.
- **Medium term:** the current capability or milestone that advances it;
  identify what remains unverified.
- **Short term:** the next falsifiable run or edit, frozen inputs, authorized
  resources and time limit, pass/fail evidence, and stop condition.

At launch, after a material result or failure, and before a retry or scope
change, ask whether the short action closes a missing medium-term evidence
gap and whether that milestone still serves the long-term objective. Search
for an already verified artifact first; reuse it when its identity matches
instead of rerunning it for a fresh timestamp. If a proposed action no longer
closes a gap, replan and update the handoff.

Record completed, active, and next work with run IDs, evidence locations, and
the remaining acceptance gap. Keep a safe running experiment alive while
checking orientation; stop only for its declared gate, safety, authority, or
resource boundary. A successor should be able to choose the same next action
from repository state without relying on chat history.
