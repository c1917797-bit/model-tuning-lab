# HYPIC 二次穿刺：全流程成功、失败与可复用经验

日期：2026-10-13。覆盖从历史成功对齐、NPU0–3 环境排障、HYPIC 实验、
性能/质量审计，到交付与 Skill 验收的整个过程；不是仅网络故障复盘。
本次只整理已留存证据，不启动设备、不重跑精度或性能、不修改历史判定。
阅读顺序：本报告 → 结构化经验 → 所引用的分阶段原始报告。

## 一、最终取得了什么

| 层级 | 已有结果 | 边界 |
|---|---|---|
| 环境性能修复 | 关闭 CPU binding 的同卡 no-cache 对照，TPOT 中位约降低 81.12% | 是环境配置改善，不是 HYPIC 收益；不等于完全定位底层通信因果 |
| 当前 HYPIC 性能 | 源码 4429e35 六阶段/三对完成；240 条计分；候选 120/120 四 worker 热证明；TPOT 中位降低 22.0163%，TTFT P95 中位降低 49.6429%，吞吐中位提高 31.7543% | 仅冻结 workload；不是质量通过或生产采用 |
| 当前完整质量 | r19 LongBench-v2 227/381→219/381，下降 2.0997pp；GSM8K 3838/3957→3840/3957 | LongBench 保留 REJECT_OR_QUALIFY；GSM8K 仅 off-path 安全 |
| 真实生命周期 | 语义 Canary 有失败；后续 operational disabled 阶段因外来 NPU3 进程在健康前终止，0 请求，自有资源释放 | 卸载/重启没有完成；不能算交付通过 |
| Skill 验收 | 29 项有案例；13 bounded verified、16 partial；六个修复文件已选择性进入 main23ec33d7 | 结构通过不等于功能全部验证，整条实验分支仍 not-ready |

**准确总结：在当前场景复现了明确的 HYPIC 加速收益；精度测试已完成但保留负结论，
质量下降根因尚未证明；生命周期与全部 Skill 验收未完成。**
不能简单把全过程叫“毫无成果”，也不能说“整体无损穿刺成功”。

性能协议：Qwen3.6-27B BF16，4×910B4/TP4，输入32768、共享16384、
固定输出1024、c16、每组每轮40条，三对独立服务生命周期。
质量协议：r19 同源码、c32、127题×3、显式分段、自然EOS、最大输出2048、
非思考；不能把固定输出性能尺混入质量尺。
后来的用户规则“思考2048/非思考1024”只作用于未来质量协议，不回写 r19。

## 二、为什么此前成功，这次仍遇到问题

1. **不是始终同一个实现。** 历史仓库参考用 3ad0967；中途有 c12060c，
   当前是 4429e35。后者包含 pending-materialization 调度保护和逐请求证明，
   不是只加日志。不能仅凭同为 v0.8.5 就宣称字节相同，更不能断言它导致了精度差。
2. **不是始终同一个测试路径。** 历史自然 chat 未附显式段边界；
   历史质量接受没有逐质量请求的 HYPIC 热路径证明。后续显式分段是新路径。
   同事 Qwen3.5/TP2 与仓库 Qwen3.6/TP4 也是两份参考。
3. **判定变严格且解释曾混淆。** 逐请求四 worker、100% 热覆盖是更强的
   机制声明要求，不能拿来抹掉全请求部署效果。r19 控制器 exit1 出现在
   全部381条保存之后，表示覆盖不足，不等于精度任务未完成或数据丢失。
   历史“重复波动范围内”与新冻结“候选不低于基线”不是同一接受规则；
   不后验改旧判定，下次必须在运行前明确匹配哪一种成功定义。
4. **0–3 的共同慢项影响相对百分比。** 相同绝对节省除以更大的基线，
   相对收益会更小；不能只凭低百分比断定卡上技术无效。CPU binding
   no-cache 对照提供了配置改善证据，HYPIC 收益必须另做同环境对照。
5. **质量差不是一句“8题失败”。** 381 是127题的三次响应；r19 四 worker 热证明为134/381，其余未证明热命中，不能全叫冷请求。
   净少8条来自
   23次退化、15次改善。按题聚合是13题退化、8题改善、106题相同。
   截断49→67、重复波动及热覆盖不足是风险线索，不是已证实单因果。
   本地 LongBench 尺有用，但不独自裁定整个论文是否有效。

## 三、做对了什么，应继续复用

- 最终回到冻结源码的一开关 A/B，用相同环境、原始响应、三轮结果和独立审计
  得到可复核的速度结论；报告绝对值、相对值、三轮波动，不只报最佳一轮。
- 完整负质量证据保留，不删冷请求、截断或错误答案；质量、机制与采用分开。
- 空闲准入后仍持续检查实际物理占用，发现外来任务只清理精确自有资源；
  映射0–7的 sleep 容器不自动等同占卡。失败根保留，未触碰外来任务。
- 终态原始证据替代过期控制器句柄作为恢复依据；同身份已完成结果不重复运行。
- 将真实发现的 planning 示例/schema、runtime 默认开关/失败路径、CLI 可执行性
  等问题修复并回归；main 只选择性集成六文件，不把失败实验实现整包合并。
- 清理交接中的陈旧 active 状态，并将历史日记与当前下一步分离；用来源绑定的
  验收案例保存成功与反例，而不是以“有 SKILL.md”判全通过。

## 四、做错、做慢和仍未解决的部分

| 问题 | 复盘判断 | 下次改变 |
|---|---|---|
| 历史参照未足够早锁定 | 源码、模型、段边界、输出/并发和成功标准混在“复现”一词里 | 开始即做差异表；历史复现和增强验收分别交付 |
| 门槛解释过宽 | 将热证明不足讲成技术失败，将完整负结果讲成还没完成 | 数据有效、质量、激活、速度、采用五栏独立报告 |
| 诊断偏离主线 | 独立 GDN 和 observer 扩展没有证明当前质量根因，却占用交付时间 | 优先现成 monkeypatch 集成测试；诊断只做一个可证伪问题并限时 |
| 容易无限追加 | 不断追求全热、全数值解释和全部历史资料，未及时交付已完整的正负结论 | 到里程碑先交付；缺失证据标缺失，另列研究问题 |
| 重复环境失败 | 启动后外来真实进程进入导致多次 pre-health 中止 | 连续守卫保留；无实际稳定窗口就交付等待状态，不消耗更多初始化 |
| 采集和解析混淆 | 有原始 profile 不等于解析门槛通过；进程 exit0 也可能内部导出失败 | 独立验证产物；旧46列/47列门槛和缺失控制器字节不追改 |
| 交接与验收漂移 | 长日记、已终态的 active 任务、旧计数/旧哈希影响恢复 | 单页当前状态、来源绑定、反例检查；历史保留不当活命令 |
| 交付生命周期不足 | CPU模板通过与真实服务启停不是一回事 | 分项报告；不靠结构测试晋级，也不因算法质量拒绝阻塞无关Skill |

这些执行问题由本次代理承担流程责任。真实占卡、拓扑漂移和网络失败确实发生，
但不能替代对身份对齐不早、诊断扩展、判定表达和交付节奏的反思。
本复盘不编造各原因占用的精确小时数；没有完整时间分账，不能定量分摊两天耗时。

## 五、下一次如何在12小时内高效拿到“可交付结论”

这是**未来任务建议模板**，不是本次新开实验授权，也不保证技术一定通过。
前提是设备可用、历史源码/模型/证据可读；墙钟截止与实际占卡时间分别记账。

| 时间预算 | 唯一产物 | 停止扩展条件 |
|---|---|---|
| 0–1h | 历史成功身份/差异表、可复用结果、缺口清单、接受规则 | 身份不明就交付缺口，不下载/重写一套新实现 |
| 1–2h | 最小集成与实际激活/禁用检查；冻结同源码协议 | 失败先界定启动/隔离/实现，不直接扩全量 |
| 2–7h | 仅补真正缺失的配对质量/性能，已匹配的完整结果复用 | 质量负结果立即保留；速度补测需符合授权，不能覆盖负结论 |
| 7–9h | 只读独立审计与一个有界诊断（仅决策需要时） | 不能区分机制就记 inconclusive，不无限扩GDN/observer |
| 9–11h | Skill义务映射、必要修复/回归、交付生命周期（范围内且有资源时） | 无历史证据不制造；无空闲窗口不停止外来任务 |
| 11–12h | 成功/失败/未证表、交接、分支提交与远端核验 | 截止交付当前结论和缺项；不擅自延长设备任务 |

每个里程碑都检查：还在验证原技术吗？新增步骤改变哪个决定？
已有证据为什么不能复用？是否未经同意增加成功门槛？剩余时间能否闭环？
若答案不明确，删除支线而不是再启动一个大测试。
