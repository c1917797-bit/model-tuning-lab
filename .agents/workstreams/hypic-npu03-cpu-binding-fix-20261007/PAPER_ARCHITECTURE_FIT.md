## Target model and mechanism fit

- User-selected checkpoint: `/cache/efim/Qwen3.6-27B` (serving alias `qwen36-hypic-e2e-2048`). The actual `config.json` reports `Qwen3_5ForConditionalGeneration` / `qwen3_5`, not a distinct Qwen3.6 architecture. Its 64 text layers contain 48 `linear_attention` and 16 `full_attention` layers, BF16, `use_cache=true`, Qwen fused/partial MRoPE geometry and 262144 configured maximum position embeddings. `config.json` SHA-256 is `69db4eb7196bc8190813231b3018ca05d8c2e3abc7b1af19d55c157af44a9d9c`; the model index SHA-256 is `a8ad2c26fb707ff8c245806315b03e3b4b74595528492423af5dae0ce39b4d9b`.
- `tokenizer_config.json` identifies `Qwen2Tokenizer` with a chat template and 262144 model length; its SHA-256 is `5186f0defcd7f232382c7f0aebcd2252d073bb921ab240e407b7ae8745d2b29b`; `tokenizer.json` SHA-256 is `5f9e4d4901a92b997e463c1f46055088b6cca5ca61a6522d1b9f64c4bb81cb42`. The model config also includes a vision tower and an MTP head; this campaign exercises text inference only and does not establish multimodal or MTP behavior.
- Paper C1 caches each independent segment's zero-start recurrent end-state and transition, then composes hot segments. Paper C2 relocates full-attention KV and repairs boundary context with a seam window. These mechanisms fit this hybrid text stack and the current vLLM-Ascend plugin seam. The formal HYPIC NPU0-3 arm already recorded real worker hot-path, GDN/attention repair and relocated segment reuse across three 40-request runs; six-unit independent performance audit passed. This is behavioral evidence for the bounded hot-reuse path, not a proof of all paper variants.
- Paper C3 schedules cold segments across independent model replicas with directory/router, scatter, transfer, combine, LPT balancing and overlap. One TP4 `vllm serve` process on NPU0-3 is one model replica, not four independent replicas. The derivative has no C3 implementation; no C3 run or claim is authorized by this experiment.

## Audited boundary and hypothesis

Read-only source audits on the exact derivative checkout returned `hot-reuse` PASS with zero source-symbol errors (`exec-0000000000000d62`) and `qwen35-single-instance` PASS with zero errors (`exec-0000000000000d63`). Expected negative audits returned `paper-complete` FAIL solely for C3.1-C3.6 (`exec-0000000000000d6a`) and `upstream-complete` FAIL for U2/U8-U12 (`exec-0000000000000d6b`). These audits check manifests and live source symbols, not NPU behavior by themselves.

Fit decision: **fits-now for this checkpoint's text-only single-instance C1/C2 hot-reuse path**, after the common supported `enable_cpu_binding=false` runtime setting; **does not fit the current service for C3**, which needs new multi-replica system implementation and resources. C1/C2 need no checkpoint retraining. The controlled hypothesis remains one variable, `VLLM_ASCEND_HYPIC_ENABLE=0/1`, with the CPU-binding repair common to both arms. Expect a within-lane performance benefit on the frozen 32768-input/16384-shared/1024-output c16 hot-reuse workload, while the separately frozen 41984-context/2048-token natural-EOS LongBench-v2 and GSM8K quality ruler must show no disallowed regression.

Open evidence: the 12-unit paired quality campaign and both exact release receipts are not complete; the HYPIC quality activation file is not yet available; the original upstream Git commit corresponding to the downloaded snapshot has not been pinned; multimodal, MTP, native-prefix coexistence, C3 and production adoption are outside this NPU0-3 test. The paper's SGLang system speedups, Qwen3.5-27B TP2 employee numbers, and this Qwen3.6-path TP4 service are different denominators and must not be pooled as absolute results.
