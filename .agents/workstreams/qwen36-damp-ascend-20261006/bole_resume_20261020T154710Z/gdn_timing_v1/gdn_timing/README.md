# Preregistered timing method

Configuration is fixed before execution: all192 frames, both layouts,
actual-selected terminal, one CPU tensor thread, four warmup pairs, twenty
sample pairs, four invocations per role per pair. Rank/layer/layout order is
fixed. AB/BA order alternates by global frame-layout index plus pair parity,
giving ten AB and ten BA sample pairs per frame-layout. Every raw batch duration
and order is retained; no outliers or frames are removed.

Both roles use the same host `perf_counter_ns` interval: NPU synchronize before
the starting timestamp, four actual calls, NPU synchronize before the ending
timestamp. This is HOST+DEVICE latency including Python dispatch, allocation,
Torch factors/ratio, compute and the final completion wait. Pre-sync is outside
the interval. It is not a device-event kernel-only metric. Mean/median/min/max
are reported per unit along with every integer batch duration. Layout aggregates
include all192 frames with no filtering and remain component-only observations.

First original use and candidate guarded compile-or-cache-load phase are timed
SEPARATELY and excluded from samples. That candidate phase includes wrapper
guards, so it is not an isolated compiler-time measurement. New in-process
specialization counts are reported; a disk-cache hit versus actual compiler
work is not inferred. Initial compile/loading and the exact-handle proof finish
before warmup and sampling. Unique actual npubin files are preserved.

New timing artifacts have a hard64MiB aggregate cap. Raw source inputs are read
one rank at a time without duplication. No new numerical tensor corpus is
exported. A failure leaves a primary receipt and any completed ranks/binaries;
partial timing cannot report complete or pass. MAIN owns stop/release and any
future independent timing-report review.
