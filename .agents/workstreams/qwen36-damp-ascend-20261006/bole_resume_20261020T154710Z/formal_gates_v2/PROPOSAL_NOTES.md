promotion occurred. No actual performance or accuracy measurements were made.

Validation performed locally: AST parse; --help; default-OFF execution without
Torch/device initialization; 21 unit checks passed. Checks cover exact pp versus
relative loss boundaries, undefined zero baseline, all-three-pairs selection,
favorable pooled statistics hiding a failing pair, SSE first-token semantics,

concurrency accounting, missing/duplicate/truncated-case score coverage, exact

fake formal manifest was generated or accepted.

The protocols specify 10% gain and three rounds but no aggregation formula.
The prospective all-three-pairs >=1.10 condition is an explicitly stronger
engineering choice, not an invented quotation of a user requirement. Freeze it
before any formal run; report pair/pooled/mean/median/geometric results together.
The composition clause is retained: real D/A/B/A+B measurements when applicable,
combined full tasks against D, actual same-source numerical component proofs.

The consumer is an evidence orchestrator, not an official benchmark replacement.
It recomputes streaming timing/counts, pairing, request/rank activation counts,
weighted item-score arithmetic and acceptance itself. Official answer extraction,
HumanEval execution, prompt rendering, raw frontend/worker joins and resource/
runtime validity must come from real executed independent readers whose audited
source packages were pinned into the policy before inference. Their concrete
implementations/receipt adapters must exist before formal admission. The supplied
proof parser is complete; it does not substitute fabricated outcomes or empty
helper stubs for those distinct readers. Existing owned RESULT receipts can be
adapted into the canonical contract only by preserving and validating their raw
Ref3s and actual PID/start/cgroup/image/devices/source/cleanup evidence.

The prepared policy cannot produce a pass. A current four-token model result
cannot satisfy the required scope: max_generated_tokens>=2048, sufficient total
context and concurrency, normal EOS, and reuse for all actual requests. The
current ongoing service candidate remains immutable and unchanged by this work.

Historical protocol files are pinned by their exact bytes/SHA256. Their expired
cutoffs are preserved. The latest user instruction is independent authority to
continue; MODEL_AUTHORITY is a technical admission horizon. This proposal creates
no new user deadline, permission question, deployment or task automation.
