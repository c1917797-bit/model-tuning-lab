# Evidence-based HE network profile revision

Prepared only. Exact HEdiagv3 RESULT93877/SHA0e107f55... and independent READBACK6036/SHAb0ed5eb4... showed: the old string-name guard failed despite networknone, uid65534, Devices[], no capabilities, a distinct guest netns, a regular sysfs metadata file and three ADMIN DOWN virtual links. This is not evidence that an arbitrary similarly named link is safe. The new predicate never classifies by gre/erspan/lo/bonding names; a rename control passes the same type/state semantics, while active/physical/peer/route/address/privilege changes fail.

Primary constants are frozen in the four public UAPI headers copied from the same stopped actual HEv3 image (network_uapi/*.h; whole hashes in HE_NETWORK_PROTOCOL.json). if.h defines IFF_UP/LOOPBACK/RUNNING/LOWER_UP/DORMANT; if_arp.h defines ARPHRD_LOOPBACK; route.h defines RTF_UP (usable) and RTF_REJECT; ipv6_route.h defines RTF_NONEXTHOP. Userspace header origin does not prove the complete implementation of the actual host kernel5.10.0-182.0.0.95.h3184.eulerosv2r13.aarch64. The narrow policy combines those constant meanings, actual per-link/proc facts, actual Docker profile, empty capability sets, and a host-owned private namespace gate. It does not infer external isolation from a carrier read error or a name.

Official primary documentation consulted: https://docs.kernel.org/networking/operstates.html explains administrative UP, operational states and driver flags; https://www.kernel.org/doc/Documentation/ABI/testing/sysfs-class-net documents flags as a hex mask, type/ifindex/iflink, carrier and operstate sysfs values. Those documents support the state interpretation, not a claim that all future kernels/images are qualified.

A regular non-symlink/non-directory sys entry must have only actual ENOTDIR child-attribute failures. Every interface must be a genuine virtual-net sysfs symlink with a distinct positive ifindex. Exactly one semantic loopback must have ARPHRD_LOOPBACK, IFF_LOOPBACK|IFF_UP, self-link, carrier1 and up/unknown state. Every nonloopback must have no UP/RUNNING/LOWER_UP/DORMANT bits, operstate down and iflink0. Carrier0 or recorded EINVAL is permitted only with those independent DOWN/link facts; EINVAL remains unavailable, never carrier0. Unknown errors and carrier1 fail. The proc dev inventory must match, with all nonloopback counters0. IPv4 main route table must contain only its exact header. This does not assert enumeration/absence of all IPv4 addresses. IPv6 addresses must be empty; IPv6 routes may contain only zero-address/prefix/no-nexthop, max-metric loopback REJECT entries without UP (flags exactly0x200200). Reference/use counters are retained unsigned metadata and are not confused with route usability. Every other route is rejected. All five capability sets must be0, UID values65534 and NoNewPrivs1.

The local predicate alone always reports standalone_network_safety_accepted=false. Before importing the official evaluator or running any control snippet, the source-verified worker prints READY with a new64hex nonce, exact source/capsule SHA, guest PID/start ticks, netns identity and actual facts. It waits at most10seconds for a root-owned mode0444 ACK in its existing private tmpfs. The host first completes the existing strong executable/UID/cgroup/CPU145/2GiB binding, opens/pins owner/PID1/live-guest namespace FDs and requires owner==PID1 and guest!=both. ACK binds nonce/source/capsule/fullCID/owned host PID/start/guest PID/netns/host identities. Guest receives no host credential or extra mount.

The host opens actual owned /proc/PID/root and tmp directory FDs, verifies the same namespace root/mount/lifetime, actual tmpfs device, rw/nosuid/nodev/noexec mount, and only writes a new source-owned ACK file. A root-owned O_EXCL/O_NOFOLLOW temp file is completely written, fsynced and made0444 before link publishes it atomically without overwriting an existing ACK. Temp unlink is through the same pinned dirfd. Legitimate publication briefly has two links; the guest accepts1 or2 only with root ownership/0444/full stable bytes. No socket, ioctl, setns, unshare, network configuration, added mount or capability is involved. Guest and independent reader replay ACK/source/process/ns identity, and check network facts again after ACK and evaluation. The READY/ACK wait and all work share original HE90/whole3600/cleanup180 budgets.

The official evaluator and executor bytes, canonical/wrong/timeout controls, scoring, input/provenance/tokenizer rules and all three task protocol bytes are unchanged. The new source explicitly revises HE runtime/capsule/reader metadata; frozen v1/v2 remain untouched. Actual same-image full15525 decoder replay, real strict HE control sandbox and a fresh independent full15525+HE/ACK evidence reader must still all pass under the new owner before software qualification.
